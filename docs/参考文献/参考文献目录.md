## 一、项目目标与技术栈（选文依据）

### 1.1 项目目标
- 场景：高校计算机课程设计小组协作，文件归集、过程留痕、作业归档、成果展示
- 核心能力：文件多端上传、挂单审核、版本快照/对比/回溯、阶段化管理、任务分工、操作日志、结项分享
- 角色：组长（管理）/ 组员（执行）/ 访客（只读查看）

### 1.2 技术栈
- 前端：Vue 3 + TypeScript + uni-app（H5 + 微信小程序）+ Pinia + Element Plus + WebUploader
- 后端：SpringBoot（Java 17）+ MyBatis-Plus + MySQL 8.0 + Redis（可选）
- 鉴权：JWT + 微信 code2Session（openid 唯一标识）
- 部署：轻量化 Tomcat / Jar 包一键启动
- 文档：Knife4j 增强 UI（`/doc.html`）

### 1.3 维度命中规则与文献引用约束
| 编号 | 维度 | 含义 |
| :---: | :---: | :---: |
| ① | 场景 | 高校 / 中小学 / 学生 / 教师场景下的文档协作、版本留痕、归档管理 |
| ② | 技术 | B/S 前后端分离、Spring Boot、uni-app / 微信小程序、MySQL、JWT、RESTful API |
| ③ | 版本 | 轻量化文件版本快照、对比、回滚 |

> **入选门槛**：① ② ③ 中至少命中 2 个维度；优先 2021-2026 文献；排除企业级协同系统、Git 底层源码研究、自媒体博客文章、纯数学/金融领域论文。
>
> **v3.2 新增硬约束**：所有期刊 / 会议论文引用必须已经在 `doc/参考文献/` 文件夹中存在对应 PDF 文件。仅 GB/T 7714-2015 第 4.7 节明确允许的 `[EB/OL]` 在线电子文献（官方权威技术文档）可不下载 PDF 直接在正文引用。

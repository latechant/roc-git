## 二、错位点明细

### 2.1 后端未接入数据库（最显著错位）

- **报告 2.1.3.1 开发环境**声称：`数据访问：MyBatis-Plus 简化 CRUD 开发`、`数据库：MySQL 8.0 持久化存储`。
- **实际情况**：`knife4j-spring/pom.xml` 仅含 `spring-boot-starter-web`、`validation`、`knife4j`、`jjwt`、`lombok`、`servlet-api`，**无 MyBatis-Plus、无 MySQL 驱动、无 Redis**；所有 Controller 直接 `new XxxVO()` 构造演示数据返回。
- **影响**：当前后端是"接口文档后端"，页面显示的均为演示数据（如项目名固定"课程设计项目"）。
- **数据库结构已重构（2026-09-23）**：`database/schema.sql` 已从 15 张表（course 体系）重构为 **22 张表**（微信 openid 用户 + group/group_member + decision/achievement/announcement/share/discussion/subscription 等），与后端实现、需求数据字典对齐。**待用户验收后执行建库，并接入后端**。
- **建议**：
  - 数据库 v2 验收通过后：执行 `database/schema.sql` + `seed.sql` 建库，后端引入 MyBatis-Plus + MySQL 驱动，Controller 改为访问 Mapper。
  - 若报告按"已实现"描述数据持久化，需后续完成上述接入；若如实描述当前为接口文档阶段，则需在报告 2.7/2.8 如实注明"数据持久化待接入"。

### 2.3 部署协议为 HTTP（非 HTTPS）

- 报告 2.1.3.3 声称：接口通过 **HTTPS 合法域名**供小程序调用。
- 实际情况：当前服务器（`116.62.81.113`）前端走 `http://`（80 端口）、后端接口走 `http://:8080`，**未配置 HTTPS 与域名**。
- **影响**：H5 端不受影响；微信小程序端因平台强制 HTTPS 合法域名，当前无法直接调后端。
- **建议**：小程序上线前需配置域名 + HTTPS 证书，并将 `api.js` 的 `BASE_URL` 指向 `https://` 域名。

### 2.4 前端接口接入状态描述过时

- 数据库 README「六、接续开发指引」第 2 条仍称：`uni-app 端目前均为 mock 数据`。
- 实际情况：**uni-app 端（前端 A）已接入真实接口**（`src/utils/api.js` + `bind-api.js`），登录/鉴权为真实 JWT，H5 页面数据来自后端真实 HTTP 调用。
- **建议**：更新数据库 README 对应描述，避免误导后续开发者。

### 2.5 技术选型文档与实现偏差

- `docs/项目可行技术栈选型…docx` 中规划了 WebUploader 分片/断点续传、Redis 缓存等。
- 实际情况：上传接口仅占位返回，未实现分片断点续传；Redis 未接入。
- **建议**：报告如需声称这些能力，需补充实现；否则如实标注为"规划能力"。

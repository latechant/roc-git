## 二、错位点明细

### 2.1 数据持久化已接入（原「未接库」作废）

- **历史状态（2026-09-23）**：`knife4j-spring` 曾仅含 web/validation/knife4j/jjwt/lombok 依赖，无 MyBatis-Plus、无 MySQL 驱动，Controller 直接 `new XxxVO()` 构造演示数据，页面显示固定演示数据。
- **当前状态（2026-09-30）**：已全面接入真实数据层：
  - `pom.xml` 新增 `mybatis-plus-boot-starter` 与 `mysql-connector-j`；
  - `application.yml` 配置 `spring.datasource`（`jdbc:mysql://127.0.0.1:3306/roc_git`，用户 `rocgit`）与 MyBatis-Plus（驼峰映射、逻辑删除 `deleted`）；
  - 22 个 Mapper、22 个 model 实体，与 `database/schema.sql` 的 22 张表一一对应；
  - Controller 注入 Service（`@Autowired`），Service 调用 Mapper 完成真实增删改查；**已无 `new XxxVO()` 演示构造**（全文仅剩 1 处普通返回）。
- **微信登录**：`WechatService` 调用真实 `code2session`（AppID/Secret 由环境变量注入），首次登录自动注册，H5 兼容昵称登录。
- **建议**：报告 2.7/2.8 可如实撰写「数据持久化已实现」，无需再标注待接入。

### 2.3 部署协议为 HTTP（非 HTTPS）

- 报告 2.1.3.3 声称：接口通过 **HTTPS 合法域名**供小程序调用。
- 实际情况：当前服务器（`116.62.81.113`）前端走 `http://`（80 端口）、后端接口走 `http://:8080`，**未配置 HTTPS 与域名**。
- **影响**：H5 端不受影响；微信小程序端因平台强制 HTTPS 合法域名，当前无法直接调后端。
- **建议**：小程序上线前需配置域名 + HTTPS 证书，并将 `api.js` 的 `BASE_URL` 指向 `https://` 域名。

### 2.4 前端接口接入状态（前端已绑定真实数据）

- uni-app 前端（前端 A）已接入真实接口（`src/utils/api.js` + `bind-api.js`），登录/鉴权为真实 JWT，H5 页面数据来自后端真实 HTTP 调用，首页已全面绑定真实数据（含空数据区域提示、无组时不回退到演示 gid）。
- **待确认**：数据库 README「六、接续开发指引」第 2 条若仍写「均使用 mock 数据」，需同步更新为「uni-app 端已接入真实接口」。

### 2.5 技术选型文档与实现偏差

- `docs/项目可行技术栈选型…docx` 中规划了 WebUploader 分片/断点续传、Redis 缓存等。
- 实际情况：文件上传已实现**整文件落盘**，但**分片/断点续传未实现**；Redis 未接入。
- **建议**：报告如需声称这些能力，需补充实现；否则如实标注为"规划能力"。
